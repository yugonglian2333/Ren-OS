一次 HTTP 请求的全貌

在网页上选中一个文件，点「上传」。浏览器得把它送到哪儿？服务器怎么知道这一串字节是一份文件？上传结束后，页面又是从哪里拿到文件名的？用同一次上传把去程和回程连起来看，URL、方法、请求体和 fetch 就各有了位置。下文的地址、文件和报文都用公开教学示例。

从点击到页面更新

浏览器拼出 URL，选定方法，准备请求体。服务器根据路径和方法找到处理函数。函数读取上传的内容，保存文件，组装响应。浏览器拿到这份响应，才有材料把新文件加进列表。

图里的实线顺着点击往下走，虚线把响应带回来。在 Chrome 的 Network 面板里，这一来一回通常合在一行。点开它，Payload 能看到发出去的数据，Response 能看到回来的内容。想观察自己的一次操作，可以先打开 DevTools，清空 Network 列表，再点按钮。页面会跳转时勾上 Preserve log，以免翻页时把刚才的记录也清掉。

URL 的每一段

https://example.com:443/documents?limit=20#recent
https://example.com:443
协议、主机名和端口一起给出访问目标。443 是 HTTPS 的默认端口，在地址栏里通常省略。
/documents
路径。这个例子用它表示文档集合。服务器可以把它交给一个函数，实现这个地址并不要求磁盘上恰好有个同名目录。
?limit=20
查询串。这里约定最多取 20 项。在 Network 点开请求的 Payload，可以从 Query String Parameters 看见浏览器实际发出的值。
#recent
片段标识。浏览器用它定位页面中的位置，发出的 HTTP 请求目标到 ?limit=20 就结束了。

请求和响应长什么样

读取列表可以用 GET。上传文件用 POST。下面按 HTTP/1.1 的文本形式写出主要字段，省去了消息长度等细节。HTTP/2、HTTP/3 使用不同的线上编码，DevTools 仍会把方法、路径和标头这些信息展示给你。

POST /documents HTTP/1.1
Host: example.com
Content-Type: multipart/form-data; boundary=UploadBoundary

--UploadBoundary
Content-Disposition: form-data; name="file"; filename="hello.txt"
Content-Type: text/plain

hello
--UploadBoundary--

第一行给出方法、请求目标和协议版本。再往下是标头。第一个空行之后才是请求体。这里的正文采用 multipart 格式，分隔符划出各个部分，name="file" 是表单字段名，filename 是随这一部分提交的文件名。

服务器创建文档后，可以这样回复：

HTTP/1.1 201 Created
Location: /documents/42
Content-Type: application/json

{"id":"42","name":"hello.txt"}

同样一个文件名，在 Payload 中出现是因为浏览器提交了它，在 Response 中出现是因为服务器返回了它。排查“文件名没显示”时，这个区别很有用。Response 有 name，就可以沿着页面读取并渲染这个字段的代码往下找。若 Response 里已经缺了它，先查接口的返回约定。

方法决定语义

方法文档接口中的含义安全幂等
GET读取文档列表或单份文档是是
HEAD读取与 GET 对应的响应标头，响应没有正文是是
POST向集合提交一份新文档否无保证
PUT在指定地址创建或整体替换文档否是
PATCH提交对已有文档的局部修改否无保证
DELETE请求删除指定文档否是

这里的「安全」描述客户端请求的语义。读列表时，服务器照样可以写访问日志。「幂等」关乎重试的后果。连续两次删除同一文档，第二次可能得到 404，文档最终仍处于已删除状态。连续两次 POST 上传同一个文件，服务端却可能生成两个编号。这正是上传超时后，值得先查一次列表再决定是否重试的原因。HTTP 方法的安全性和幂等性

数据放在哪里

位置这次请求里装什么在 Network 哪里看
Path/documents/42 指定某一份文档Headers → Request URL
Query?limit=20 指定读取条件Payload → Query String Parameters
HeaderContent-Type 描述正文格式Headers → Request Headers
Body上传的表单或文件内容，也可以是 JSONPayload → Form Data 或 Request Payload

如果“只传了一个文件，为什么 Payload 里看不到 JSON”，看一眼请求的 Content-Type。上传示例声明的是 multipart/form-data，打开的是包含文件的表单。JSON 出现在另一边，那是服务器返回的文档信息。

fetch 是什么

fetch 是这里的浏览器代码用来发送请求的函数。下面两段沿用上面的示例接口。第一段取列表，第二段接收从文件输入框选中的 File 对象。

async function listDocuments() {
  const response = await fetch("/documents?limit=20");
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

async function uploadDocument(file) {
  const form = new FormData();
  form.append("file", file);
  const response = await fetch("/documents", { method: "POST", body: form });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return response.json();
}

两处 await 在等不同的东西。fetch 在响应标头可用时交回 Response，正文可能还在路上；json() 会读完正文再解析。服务端即使回了 404，前一个 Promise 也可能正常完成，所以代码在解析前检查 ok。如果报的是 JSON 解析错误，点 Response 看一眼原文。有时第一行就是一张登录页的 <!doctype html>。

上传时直接把 FormData 交给 fetch，由浏览器生成带 boundary 的 Content-Type。若改发 JSON，才需要把对象序列化，并声明相应的内容类型。MDN 的 Fetch 用法

同一次点击，谁在发请求？

  1. HTML 表单。默认提交可以触发页面导航。在 Network 里只看 Fetch/XHR，可能把这次文档请求藏掉了。
  2. XMLHttpRequest。脚本在后台发请求，收到数据后局部更新页面。这是常说的 AJAX 的一种实现。
  3. fetch。同样能在原页面更新数据。Network 的 Initiator 可以帮你找到触发请求的脚本。
  4. 服务端渲染。浏览器请求一个页面，应用服务器可能再向上游读取文档。Network 能记录浏览器发出的页面请求；服务端到上游的那段耗时要到服务端日志或追踪记录里看。

回到 DevTools，看一次上传卡在哪儿

在 Network 选中上传请求，读一遍 Payload 和 Response，已经能分清文件有没有发出、服务端有没有返回编号。如果症状是“上传很慢”，再打开 Timing。Request sent 很长，可以继续看上传大小与上行带宽；Waiting for server response 很长，则要把往返延迟和服务端准备响应的时间都考虑进去。即使响应只有几十字节，等第一个字节也可能花去大半秒。

要是响应早就结束了，列表仍然不更新，换个方向。点 Initiator 回到提交函数，在 await uploadDocument(file) 的下一行下断点，再用测试文件复现一次。暂停后看返回对象里的 name，接着看传给渲染函数的是哪个字段。这两眼就能把“上传成功了但看不到文件”缩小到一小段代码。Chrome 的 Timing 说明
